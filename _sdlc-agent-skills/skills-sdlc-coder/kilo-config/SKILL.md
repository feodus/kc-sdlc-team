# KiloCode Настройка и Кастомизация

Полный навык по кастомизации KiloCode, объединяющий создание агентов, навыков, правил и конфигураций.

## Быстрые ссылки

- **Workflows:** `references/repository-workflows.md`
- **Шаблоны агентов:** `templates/`
- **Примеры агентов:** `examples/`
- **Фрагменты документации:** `parts/`

## Обзор навыка

Этот навык предоставляет комплексное руководство по настройке KiloCode:

1. **Custom Agents** — Создание кастомных агентов с YAML frontmatter
2. **Skills** — Создание и управление навыками
3. **Custom Rules** — Определение правил поведения
4. **Custom Instructions** — Добавление гайдлайнов
5. **Workflows** — Автоматизация многошаговых процессов
6. **Context & Indexing** — Индексация кодовой базы

## Когда использовать

- Создание новых кастомных агентов для KiloCode
- Настройка разрешений и доступа к инструментам
- Создание навыков (skills) для расширения возможностей
- Определение правил для проекта
- Настройка конфигурации в kilo.jsonc
- Миграция со старого формата `.kilocodemodes`
- Выполнение регламентных работ с репозиторием (коммиты, синхронизация, очистка артефактов)

## Часть 1: Custom Agents

### Формат файлов

Создавай `.md` файлы в директории `.kilo/agent/`:

```
.kilo/agent/
└── my-agent.md    # Один агент на файл
```

### Обязательные поля Frontmatter

| Поле | Описание |
|------|---------|
| `description` | Когда использовать этого агента |
| `mode` | `primary` / `subagent` / `all` |
| `permission` | Разрешения инструментов |

### Дополнительные поля Frontmatter

| Поле | Описание |
|------|---------|
| `color` | Hex цвет для UI (например, `"#FF5733"`) |
| `skills` | Список навыков для активации |
| `model` | Модель в формате `provider/model-id` |
| `temperature` | Температура генерации (0-1) |
| `steps` | Максимум итераций агента |

### Пример: Полный агент

```yaml
---
description: Мощный Python разработчик с экспертизой в FastAPI и Django
mode: primary
color: "#FF5733"
skills:
  - fastapi-development
  - python-project-setup
  - python-testing
permission:
  bash: allow
  edit:
    "*.py": allow
    "src/**": allow
  read:
    "*": allow
  glob:
    "*": allow
  grep:
    "*": allow
  task: allow
  webfetch: allow
  websearch: allow
  codesearch: allow
  external_directory: allow
---

# Python Developer Agent

Ты эксперт Python разработки, специализирующийся на FastAPI, Django и обработке данных.
```

### Система разрешений

#### Поля разрешений

| Инструмент | Описание |
|------------|----------|
| `bash` | Выполнение команд |
| `edit` | Редактирование файлов |
| `read` | Чтение файлов |
| `glob` | Поиск файлов |
| `grep` | Поиск по содержимому |
| `task` | Вызов подзадач |
| `webfetch` | Получение веб-страниц |
| `websearch` | Веб-поиск |
| `codesearch` | Поиск кода |

#### Значения разрешений

- `allow` — Разрешить доступ
- `deny` — Запретить доступ
- `ask` — Запросить подтверждение

#### Ограничения файлов

Используй glob-паттерны для ограничения доступа к файлам:

```yaml
permission:
  edit:
    "src/**": allow      # Разрешить src директорию
    "*.{py,js}": allow   # Разрешить конкретные расширения
    "*": deny            # Запретить всё остальное
```

### Режимы агентов

| Режим | Описание |
|-------|----------|
| `primary` | Пользовательский агент, виден в списке выбора |
| `subagent` | Только для вызова через task tool |
| `all` | Используется и как агент, и как подзадача |

### Расположение агентов

| Область | Путь |
|---------|------|
| Проект | `.kilo/agent/*.md` |
| Глобально | `~/.config/kilo/agent/*.md` |

### Приоритет конфигурации

1. **Встроенные агенты** (по умолчанию)
2. **Глобальная конфигурация** (`~/.config/kilo/kilo.jsonc`)
3. **Проектная конфигурация** (`kilo.jsonc`)
4. **Файлы агентов** (`.kilo/agent/*.md`)

### Шаблоны агентов

См. `templates/` директорию для готовых шаблонов.

## Часть 2: Skills (Навыки)

### Что такое Skills

Skills — это модульные пакеты, расширяющие возможности агента специализированными знаниями и workflows. Это как "онбординг гайды" для конкретных доменов.

### Как работают Skills

1. **Обнаружение**: При инициализации сканируются директории навыков
2. **Включение в промпт**: Метаданные навыков добавляются в system prompt
3. **Загрузка по требованию**: Агент загружает полный SKILL.md когда решает использовать навык

### Анатомия навыка

Каждый навык состоит из обязательного SKILL.md и опциональных ресурсов:

```
skill-name/
├── SKILL.md (обязательно)
│   ├── YAML frontmatter метаданные
│   └── Markdown инструкции
└── Дополнительные ресурсы (опционально)
    ├── scripts/          # Исполняемый код
    ├── references/      # Документация
    └── assets/         # Файлы для вывода
```

### Формат SKILL.md

#### Обязательные поля Frontmatter

| Поле | Описание |
|------|---------|
| `name` | Макс 64 символа, lowercase, цифры, дефисы |
| `description` | М��кс 1024 символа, когда использовать |

#### Опциональные поля

| Поле | Описание |
|------|---------|
| `license` | Лицензия (MIT, Apache-2.0) |
| `compatibility` | Требования к окружению |
| `metadata` | Дополнительные свойства |

### Правило соответствия имени

В KiloCode поле `name` **должно совпадать** с именем папки:

```
✅ Правильно:
skills/
└── api-design/
    └── SKILL.md  # name: api-design

❌ Неправильно:
skills/
└── api-design/
    └── SKILL.md  # name: my-api-skill  (не совпадает!)
```

### Расположение навыков

#### Глобальные навыки

- Mac/Linux: `~/.kilo/skills/`
- Windows: `C:\Users\<user>\.kilo\skills\`

#### Проектные навыки

```
your-project/
└── .kilo/
    └── skills/
        └── my-skill/
            └── SKILL.md
```

#### Дополнительные пути

В `kilo.jsonc`:

```jsonc
{
  "skills": {
    "paths": ["/path/to/skills", "~/my-skills"],
    "urls": ["https://example.com/skills/SKILL.md"]
  }
}
```

### Принцип Progressive Disclosure

Навыки используют трёхуровневую систему загрузки:

1. **Метаданные** (name + description) — Всегда в контексте
2. **SKILL.md body** — При активации навыка
3. **Ресурсы** — По требованию

### Принципы дизайна

1. **Разделяй логику** (детерминированная vs агентная):
   - Если нужна точность — используй скрипты в `scripts/`
   - Если нужна интерпретация — оставь LLM

2. **Progressive Disclosure**:
   - SKILL.md должен быть компактным (до 500 строк)
   - Глубокая документация — в `references/`

3. **Конституция, не советы**:
   - Пиши в повелительной форме ("Allгда делай X", "Никогда не меняй Y")

### Пошаговое создание навыка

#### Шаг 1: Понимание

Чётко понимай конкретные примеры использования навыка.

#### Шаг 2: Планирование

Анализируй каждый пример:
- Какие скрипты нужны?
- Какая документация нужна?
- Какие ассеты нужны?

#### Шаг 3: Структура

Создай папку навыка:
- `SKILL.md` (обязательно)
- `scripts/` (если нужно)
- `references/` (если нужно)
- `assets/` (если нужно)

#### Шаг 4: Frontmatter

Заполни обязательные поля:
- **name**: должно совпадать с именем папки
- **description**: включай ключевые слова для активации

#### Шаг 5: Инструкции

Раздели Markdown на секции:
1. **О навыке** — краткое объяснение
2. **Когда использовать** — триггеры
3. **Принципы дизайна** — основные правила
4. **Инструкции** — шаги выполнения
5. **Примеры** — few-shot prompting

#### Шаг 6: Итерация

Тестируй на реальных задачах и улучшай.

## Часть 3: Custom Rules

### Создание правил

Правила в `.kilo/rules/`:

```jsonc
// kilo.jsonc
{
  "instructions": [".kilo/rules/formatting.md", ".kilo/rules/*.md"]
}
```

### Типы правил

| Тип | Описание |
|-----|----------|
| Project Rules | Применяются только к текущему проекту |
| Global Rules | Применяются ко всем проектам |

### Примеры правил

#### Форматирование таблиц

```markdown
# Таблицы

При создании таблиц всегда добавляй восклицательный знак к каждому заголовку колонки
```

#### Ограничение доступа

```markdown
# Защищённые файлы

Файлы из списка содержат чувствительные данные, их НЕЛЬЗЯ читать

- supersecrets.txt
- credentials.json
- .env
```

## Часть 4: Workflows

### Создание Workflows

Workflows — это markdown файлы в `.kilo/commands/`:

```
.kilo/commands/
└── submit-pr.md    # Вызывается через /submit-pr
```

### Опциональный Frontmatter

```yaml
---
description: Submit pull request с проверками
agent: code
model: anthropic/claude-sonnet-4-20250514
subtask: true
---

# Submit PR Workflow

Ты помогаешь отправить pull request...

1. Проверь TODO комментарии
2. Запусти тесты
3. Закоммить изменения
4. Создай PR
```

### Паттерны Workflows

- **Релиз менеджмент** — управление версиями
- **Настройка проекта** — инициализация
- **Подготовка code review** — проверки перед ревью

## Часть 5: Конфигурация

### kilo.jsonc Основные поля

```jsonc
{
  "$schema": "https://app.kilo.ai/config.json",
  
  // Agent конфигурация
  "agent": {
    "my-agent": {
      "description": "Мой агент",
      "mode": "primary",
      "prompt": "Ты эксперт..."
    }
  },
  
  // Rules
  "instructions": [".kilo/rules/*.md"],
  
  // Skills
  "skills": {
    "paths": ["./skills/"],
    "urls": ["https://..."]
  },
  
  // MCP серверы
  "mcp": {
    "servers": {}
  }
}
```

## Часть 6:agents.md

### Расположение

AGENTS.md размещается в корне проекта:

```
my-project/
├── AGENTS.md          # Основное имя (рекомендуется)
├── AGENT.md          # Альтернативное имя
└── src/
```

### Рекомендуемая структура

```markdown
# Project Name

Краткое описание проекта.

## Code Style

- Используй TypeScript для всех новых файлов
- Следуй ESLint конфигурации
- Используй 2 пробела для отступов

## Architecture

- Следуй MVC паттерну
- Компоненты до 200 строк
- Используй dependency injection

## Testing

- Пиши юнит-тесты для бизнес-логики
- Покрытие >80%
- Используй Jest
```

## Troubleshooting

| Проблема | Решение |
|----------|---------|
| Агент не появляется | Перезагрузи VS Code |
| Разрешение отклонено | Проверь glob паттерны |
| Skills не загружаются | Проверь пути в kilo.json |
| Навык не активируется | Проверь описание в frontmatter |
