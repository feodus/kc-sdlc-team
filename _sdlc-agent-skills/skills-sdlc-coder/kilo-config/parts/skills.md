# Skills — Полное руководство

## Когда использовать

- Создание новых навыков с нуля
- Рефакторинг существующих промптов в модульные навыки
- Настройка директории навыков (scripts/, references/, assets/)
- Отладка навыков которые не активируются
- Понимание Agent Skills specification

---

## Что такое Skills

Skills — модульные, самодокументируемые пакеты, расширяющие возможности агента специализированными знаниями и workflows. Это как "онбординг гайды" для конкретных доменов.

### Что предоставляют Skills

1. **Специализированные workflows** — Многошаговые процедуры
2. **Интеграции с инструментами** — Инструкции для работы с форматами/API
3. **Доменную экспертизу** — Компания-специфичные знания, схемы, бизнес-логика
4. **Bundled ресурсы** — Скрипты, референсы, ассеты

### Ключевые преимущества

- **Самодокументируемость**: SKILL.md легко читается и аудируется
- **Интероперабельность**: Работают с любым агентом поддерживающим Agent Skills spec
- **Расширяемость**: От простых инструкций до сложных скриптов
- **Переносимость**: Легко шарить между проектами

## Анатомия навыка

### Структура

```
skill-name/
├── SKILL.md (обязательно)
│   ├── YAML frontmatter метаданные
│   └── Markdown инструкции
└── Дополнительные ресурсы (опционально)
    ├── scripts/          # Исполняемый код
    ├── references/      # Документация
    └── assets/         # Файлы для вывода
```

### SKILL.md (обязательно)

**Метаданные**: Поля `name` и `description` определяют когда агент активирует навык. Будь конкретен.

**Тело**: Инструкции, примеры, референсы.

### Bundled Resources (опционально)

#### Scripts (`scripts/`)

Исполняемый код для задач требующих детерминированной надёжности.

- **Когда включать**: Когда тот же код переписывается многократно
- **Преимущества**: Эффективно по токенам, детерминировано
- **Примечание**: Может потребоваться патчинг под окружение

#### References (`references/`)

Документация для загрузки по требованию.

- **Когда включать**: Для документации которую агент должен читать
- **Примеры**: API спецификации, схемы БД
- **Лучшая практика**: Если файлы >10k слов, включи grep паттерны

#### Assets (`assets/`)

Файлы не для загрузки в контекст, а для использования в выводе.

- **Когда включать**: Когда навык использует файлы в финальном выводе
- **Примеры**: Шаблоны, лого, HTML boilerplate

## Формат SKILL.md

### Обязательные поля Frontmatter

| Поле | Требования | Описание |
|------|------------|----------|
| `name` | Макс 64 символа, lowercase, цифры, дефисы (не начинать/кончать с -) | Идентификатор навыка |
| `description` | Макс 1024 символа | Когда использовать навык |

### Опциональные поля

| Поле | Описание |
|------|----------|
| `license` | Имя лицензии |
| `compatibility` | Требования окружения |
| `metadata` | Произвольные key-value |
| `allowed-tools` | Список разрешённых инструментов |

### Пример Frontmatter

```yaml
---
name: pdf-processing
description: Извлечение текста и таблиц из PDF, заполнение форм, объединение документов.
license: Apache-2.0
metadata:
  author: example-org
  version: 1.0.0
allowed-tools: read write execute
---

## Инструкции

### Как извлечь текст

1. Используй pdfplumber...
```

### Правило соответствия имени

В KiloCode поле `name` **должно совпадать** с именем папки:

```
✅ Правильно:
skills/
└── api-design/
    └── SKILL.md  # name: api-design

❌ Неправильно:
skills/
└── api-design/
    └── SKILL.md  # name: my-api-skill  (не совпадает!)
```

## Progressive Disclosure

Трёхуровневая система для эффективного управления контекстом:

1. **Метаданные** (name + description) — Всегда в контексте (~100 слов)
2. **SKILL.md body** — При активации навыка (<5k слов рекомендуется)
3. **Bundled ресурсы** — По требованию (безлимитно для скриптов)

*Скрипты могут исполняться без загрузки в контекст.*

## Принципы дизайна

### 1. Разделяй логику

- **Детерминированные задачи** → скрипты в `scripts/`
- **Агентные задачи** → LLM

### 2. Progressive Disclosure

- SKILL.md компактный (до 500 строк)
- Глубокая документация → `references/`
- Шаблоны → `assets/`

### 3. Конституция, не советы

Пиши в повелительной форме:
- "Allгда делай X"
- "Никогда не меняй Y"

## Лучшие практики

### Структурирование

1. **Single Responsibility**: Один файл = одна область
2. **Иерархическая организация**: Ясная структура заголовков
3. **Специфичность**: Избегай общих формулировок
4. **Примеры**: Включай конкретные примеры

### Рекомендуемая структура

```
.kilocode/rules/
├── 00-general.md         # Основные принципы
├── 10-security.md        # Безопасность (высокий приоритет)
├── 20-structure.md      # Архитектура
├── 30-naming.md        # Соглашения об именовании
├── 40-formatting.md    # Стиль кода
├── 50-testing.md      # Тестирование
└── 90-workflows.md    # Специфичные workflows
```

### Язык

- **Повелительное наклонение**: "MUST", "SHOULD", "NEVER"
- **Ясность формулировок**: Без двусмысленности
- **Контекст**: Достаточно контекста для понимания
- **Исключения**: Чётко описывай особые случаи

## Пошаговое создание навыка

### Шаг 1: Понимание

Понять конкретные примеры использования навыка. Что пользователь будет спрашивать?

### Шаг 2: Планирование

| Запрос | Ресурс | Расположение |
|---------|--------|-------------|
| "Rotate PDF" | rotation code | `scripts/rotate.sh` |
| "Build todo app" | HTML template | `assets/todo-template/` |
| "Query users" | Schema docs | `references/schema.md` |

### Шаг 3: Инициализация структуры

```
my-skill/
├── SKILL.md
├── scripts/      # Если нужно
├── references/   # Если нужно
└── assets/      # Если нужно
```

### Шаг 4: Заполнение Frontmatter

- **name**: Совпадает с именем папки
- **description**: Ключевые слова для активации

### Шаг 5: Написание инструкций

1. **## About** — Краткое объяснение
2. **## When to use** — Триггеры
3. **## Design Principles** — Правила
4. **## Instructions** — Шаги
5. **## Examples** — Few-shot

### Шаг 6: Итерация

Тестируй → Замечай проблемы → Улучшай → Тестируй снова

## Troubleshooting

### Проверка активации

- Запроси активацию и смотри логи
- Ищи `read` вызов для SKILL.md

### Если навык не активируется

1. Проверь описание в frontmatter
2. Пере��агрузи VS Code / сессию
3. Проверь структуру директорий

### Если навык активируется но не следует инструкциям

1. Ясность описания в frontmatter
2. Использование повелительной формы
3. Правильная структура секций

### Частые ошибки

| Ошибка | Причина | Решение |
|--------|---------|---------|
| "missing required 'name' field" | Нет name в frontmatter | Добавь `name: skill-name` |
| "name doesn't match directory" | Несовпадение | name должен совпадать точно |
| Skill not appearing | Неправильная структура | Проверь путь `skills/skill-name/SKILL.md` |
