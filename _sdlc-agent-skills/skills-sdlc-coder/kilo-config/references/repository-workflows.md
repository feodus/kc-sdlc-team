# Регламенты работы с репозиторием (Workflows & Common Tasks)

Данный документ содержит пошаговые инструкции по эксплуатации и расширению экосистемы KiloCode SDLC.

## 1. Работа с Git и Коммитами

### Workflow: Создание коммита (Русский)
1. **Проверить изменения:** `git status --porcelain`
2. **Получить diff:** `git add . && git diff --staged`
3. **Сгенерировать сообщение:** Conventional Commits на русском (`feat: добавить новую кнопку`)
4. **Подтвердить с пользователем:** Показать сгенерированное сообщение
5. **Зафиксировать:** `git commit -m "{message}"`
6. **Отправить:** `git push`

### Workflow: Создание коммита (Английский)
1. **Проверить изменения:** `git status --porcelain`
2. **Получить diff:** `git add . && git diff --staged`
3. **Сгенерировать сообщение:** Conventional Commits на английском (`feat: add new login button`)
4. **Подтвердить с пользователем:** Показать сгенерированное сообщение
5. **Зафиксировать:** `git commit -m "{message}"`
6. **Отправить:** `git push`

## 2. Расширение экосистемы

### Workflow: Добавление нового режима
1. Создать директорию для нового режима.
2. Создать YAML-файл конфигурации в `.kilocodemodes`.
3. Добавить документацию и навыки.
4. Обновить `AGENTS.md`.
5. Протестировать новый режим.

### Workflow: Добавление нового навыка (Skill)
1. Создать директорию в папке навыков режима.
2. Создать файл `SKILL.md` с метаданными и инструкциями.
3. Обновить `AGENTS.md` (секция Skills Reference).
4. Обновить конфигурацию режима при необходимости.

---

## 3. Поддержка документации

### Workflow: Обновление AGENTS.md
1. Проверить текущие изменения в git (`git status`).
2. Определить тип изменений (добавление/удаление компонентов).
3. Обновить соответствующие разделы.
4. Обновить метаданные (дата, версия).
5. Проверить ссылочную целостность.

### Workflow: Синхронизация документации проекта
1. **Git Commit (локально):** `git add -A` $\rightarrow$ `git commit` (без push).
2. **AGENTS.md Update:** обновление метаданных, Changelog, структуры проекта.
3. **Проверка ссылок:** валидация внутренних ссылок.

---

## 4. Техническое обслуживание

### Workflow: Очистка артефактов проекта
1. **Проверить директорию:** убедиться что `project_artifacts/` существует.
2. **Проанализировать содержимое:** рекурсивно найти все файлы, подсчитать их количество.
3. **Запросить подтверждение:** сообщить пользователю количество файлов и директорий, что все файлы будут удалены permanently.
4. **Выполнить очистку:** удалить все файлы рекурсивно, сохранив директории.
5. **Проверить результат:** убедиться что файлов не осталось, структура папок сохранена.
